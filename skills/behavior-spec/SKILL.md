# 从共识到行为规格

读取已确认需求、领域约束和相关架构决定。保留来源，分开记录现有行为、目标行为与不兼容变化。已有规格时增量更新，不另建矛盾版本。

## 行为规格

描述用户触发、输入与前置条件、可观察输出、错误与取消行为、数据归属、兼容范围和不做事项。为关键行为分配 R-ID，为验收分配 AC-ID，并注明对应关系。

识别 Seam：真实调用边界上可隔离、替换或验证的连接点。说明怎样触发用户所述行为，避免把内部函数方便测试误作边界正确。

使用 [规格与任务格式](references/spec-and-slices.md) 建立验收矩阵。没有掌握的规则保持未决，不自行补写为要求。

## 竖切任务

先规划能穿过真实前端、接口、业务和存储/外部执行边界的最薄完整路径，再增量扩展；按项目实际层次选择，不为示范引入无用层。

每个切片注明：业务结果、依赖、输入输出契约、Seam、验收方法、允许修改范围。保留实现自由，不提前写死未经过验证的函数名、文件名和命令步骤。

对会影响结果的未决需求交回对齐；对已确定部分继续完成规格。规格审阅后可用 `vertical-slice-build` 实现；不因生成文档自动执行未授权的代码改写。
