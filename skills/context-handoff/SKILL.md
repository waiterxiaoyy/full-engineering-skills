# 保存与恢复上下文

只保存能改变下一步判断的内容。以当前任务为单位，区分用户原始目标、已确认结论、Agent 提案、已观察事实、未执行计划及阻塞条件。

## 保存

- 探索中尚未形成稳定规格：保存交接文档，包含已确认决策、待决策前沿、来源和继续工作的入口。
- 已有规格：增量更新规格，再记录实现进度与下一步，避免复制出另一份完整且相互矛盾的需求。
- 需求过大：拆成互相引用、带依赖的专题规格；不把所有内容塞入一条摘要。

保留关键反例、边界、用户否定过的方案和理由，以及当前运行目录、修改范围、关键命令与结果文件。不要复制密钥或登录凭据。

在实际出现细节遗漏风险或切换会话前保存，不凭固定 token 百分比判断模型能力。不假定 IDE 提供 `/compact`、`/handoff` 或能控制其他会话；普通 Markdown 文件也能完成交接。

## 恢复

新会话先读取交接文件及其指定的权威规格、决策和必要代码；核对工作树与记录是否一致。说明已恢复的阶段、仍然未定的事项和接下来的动作，然后继续。遇到新事实优先更新记录，不能让旧摘要覆盖新代码或用户指令。
