# 领域共识与决策

读取现有领域说明和相关 ADR，只记录从代码中不容易还原、且会改变后续判断的知识。

## 记录什么

- 在用户指定的 CONTEXT.md 中保存领域术语、含义、适用上下文、业务不变量和稳定约束。
- 在 ADR 中保存重要决策的背景、考虑过的方案、选择理由、代价、状态及来源。
- 目录结构、可快速检索的代码细节、经常变化的实现值留在代码中，不建立重复镜像。
- 将待确认结论标为提案；用户已表达的决定无需再次请求批准。

## 更新过程

1. 将本轮新结论与已有记录对照；同一个词含义不一致时显式消解上下文。
2. 仅在决策有持久价值时新增 ADR；普通局部实现无需强行记录。
3. 改变旧决策时保留历史，并将其标为被新的 ADR 取代；明确新决定影响哪些规格或测试。
4. 输出本轮新增或变化的知识，以及下一步应读取的文件。

用 [记录模板](references/knowledge-records.md) 起草。模板中的栏目按需要裁剪，不为凑齐栏目编造信息。
