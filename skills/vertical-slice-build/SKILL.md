# 竖切全栈实现

读取当前规格、切片依赖、领域约束及授权修改范围。检查实际工作树；已有本地修改需要保留。一个工作区包含多个仓库时分别定位，不假定父目录有 Git。

## 选择当前切片

先完成依赖满足的一条最薄业务链路，使界面、请求、后端执行与结果形成可观察闭环；后续切片复用这条路径扩展能力。不要先完成全部数据层，再全部后端，最后才第一次联调。

若仅有模糊目标、且缺口会改变正确性，指出具体问题；已有足够规格时直接实现，不重复整套需求访谈。

## 在边界上验证

- 找到能触发目标行为的 Seam，关键路径先写会因缺少该行为而失败的测试，真实运行失败，再实现并运行通过，必要时重构。
- 普通胶水代码采用项目正常开发方式。不要为覆盖率为每个私有函数补镜像测试。
- 使用真实契约连接前后端；明确测试替身覆盖的边界及尚未接通的服务。
- 按受影响范围运行已有类型检查、构建、测试和实际链路验证；缺少脚本时明确，不捏造 `npm test` 等命令。
- 新发现的业务规则回写规格和决策；局部实现选择可自主处理。行为变化与旧版差异需要说明原因。

## 交付

给出切片业务结果、关键 diff、AC-ID 对应证据、剩余切片和已知限制。编译通过不代表浏览器链路通过；模拟结果不代表真实 AI 或远程系统通过。

定位不明的失败可用同包 `evidence-debugging`；需要保存进度或交接时可用同包 `context-handoff`。不自动提交、推送、部署或操作共享数据库。
